# Electron 渲染进程与主进程区分及 Preload 脚本深度解析

## 1. 主进程 vs 渲染进程：核心区别

### 1.1 主进程（Main Process）

**定义**：每个 Electron 应用只有一个主进程，它是应用的入口点，运行在 Node.js 环境中。

**特征**：
- 使用 `BrowserWindow` 实例创建和管理窗口
- 负责应用生命周期（启动、退出、激活等）
- 可以访问完整的 Node.js API 和系统资源
- 可以注册全局快捷键、菜单、Tray 等
- 通过 IPC 与渲染进程通信

**典型代码示例**：
```javascript
// main.js
const { app, BrowserWindow } = require('electron');

let mainWindow;

app.whenReady().then(() => {
  mainWindow = new BrowserWindow({
    width: 800,
    height: 600,
    webPreferences: {
      preload: path.join(__dirname, 'preload.js')
    }
  });
  
  mainWindow.loadFile('index.html');
});
```

### 1.2 渲染进程（Renderer Process）

**定义**：每个 `BrowserWindow` 实例都运行在独立的渲染进程中，负责显示网页内容。

**特征**：
- 运行在 Chromium 环境中，类似于浏览器
- **默认情况下**无法直接访问 Node.js API
- 负责 UI 渲染和用户交互
- 通过 IPC 与主进程通信
- 支持 HTML/CSS/JavaScript

**典型代码示例**：
```html
<!-- index.html -->
<!DOCTYPE html>
<html>
<body>
  <h1>Hello Electron</h1>
  <script>
    // 默认无法访问 require('fs')
    // 需要通过 preload 暴露的 API
    window.electronAPI.sendMessage('Hello from renderer');
  </script>
</body>
</html>
```

### 1.3 快速对比表

| 特性 | 主进程 | 渲染进程 |
|------|--------|----------|
| **数量** | 唯一（1个） | 多个（每个窗口1个） |
| **环境** | Node.js | Chromium（浏览器） |
| **Node.js API** | ✅ 完全访问 | ❌ 默认禁止 |
| **DOM 操作** | ❌ 无法直接操作 | ✅ 完全支持 |
| **GUI 创建** | ✅ 创建窗口 | ❌ 无法创建 |
| **生命周期** | 应用级别 | 窗口级别 |
| **IPC 通信** | `ipcMain` | `ipcRenderer` |

## 2. Preload.js：安全的桥梁

### 2.1 什么是 Preload.js？

`preload.js` 是在渲染进程加载网页内容**之前**执行的脚本，它运行在一个特殊的上下文中，既能够访问 Node.js API，又能够安全地暴露功能给渲染进程。

### 2.2 Preload 的核心作用

1. **安全桥接**：在隔离的渲染进程和主进程之间建立安全的通信渠道
2. **暴露受控 API**：有选择性地暴露 Node.js 功能，而非全量开放
3. **环境初始化**：在页面加载前执行初始化逻辑
4. **数据预处理**：对从主进程接收的数据进行格式化

### 2.3 为什么 Preload 能访问 Node.js API？

关键在于 Electron 的**上下文隔离（Context Isolation）**和**沙箱机制**：

```javascript
// preload.js - 传统方式（Electron 12+ 推荐使用 contextBridge）
const { contextBridge, ipcRenderer } = require('electron');

// ✅ 正确：通过 contextBridge 安全暴露 API
contextBridge.exposeInMainWorld('electronAPI', {
  sendMessage: (message) => ipcRenderer.send('message', message),
  receiveResponse: (callback) => ipcRenderer.on('response', callback)
});

// ❌ 危险：直接暴露 Node.js 对象
// window.fs = require('fs'); // 这会破坏安全性
```

**技术原理**：

1. **进程隔离**：Preload 脚本运行在渲染进程的上下文中，但拥有特殊的权限
2. **Node.js 集成**：当 `nodeIntegration` 为 `false` 时，渲染进程无法访问 Node.js，但 Preload 可以在独立作用域中访问
3. **上下文桥接**：通过 `contextBridge` API，安全地将功能从特权上下文传递到非特权上下文
4. **沙箱逃逸**：Preload 脚本在隔离的 V8 上下文中执行，但仍可访问 Node.js 的全局对象

### 2.4 完整的 Preload 使用示例

```javascript
// preload.js
const { contextBridge, ipcRenderer, shell } = require('electron');
const fs = require('fs');

// 暴露安全的 API 给渲染进程
contextBridge.exposeInMainWorld('secureAPI', {
  // IPC 通信
  send: (channel, data) => {
    const validChannels = ['toMain', 'userAction'];
    if (validChannels.includes(channel)) {
      ipcRenderer.send(channel, data);
    }
  },
  
  receive: (channel, callback) => {
    const validChannels = ['fromMain', 'statusUpdate'];
    if (validChannels.includes(channel)) {
      ipcRenderer.on(channel, (event, ...args) => callback(...args));
    }
  },
  
  // 文件系统操作（受控）
  readFile: (path) => {
    return new Promise((resolve, reject) => {
      fs.readFile(path, 'utf8', (err, data) => {
        if (err) reject(err);
        else resolve(data);
      });
    });
  },
  
  // 打开外部链接
  openExternal: (url) => shell.openExternal(url)
});

// 页面加载完成后执行
window.addEventListener('DOMContentLoaded', () => {
  console.log('Preload script executed');
});
```

## 3. 安全实践：最佳配置

### 3.1 推荐的 WebPreferences 配置

```javascript
// main.js
const mainWindow = new BrowserWindow({
  width: 800,
  height: 600,
  webPreferences: {
    // ✅ 启用上下文隔离（必需）
    contextIsolation: true,
    
    // ✅ 禁用 Node.js 集成（安全）
    nodeIntegration: false,
    
    // ✅ 使用 Preload 脚本
    preload: path.join(__dirname, 'preload.js'),
    
    // ✅ 启用沙箱（可选，增强安全）
    sandbox: true
  }
});
```

### 3.2 安全等级对比

| 配置 | 安全性 | 功能访问 | 使用场景 |
|------|--------|----------|----------|
| `nodeIntegration: true` | ❌ 低 | ✅ 完全 Node.js | 开发环境（不推荐生产） |
| `contextIsolation: false` | ⚠️ 中 | ⚠️ 直接访问 Node.js | 旧项目迁移 |
| `contextIsolation: true` + Preload | ✅ 高 | ✅ 受控 API | ✅ 生产环境推荐 |

## 4. IPC 通信模式

### 4.1 单向通信（渲染 → 主进程）

```javascript
// preload.js
contextBridge.exposeInMainWorld('api', {
  sendToMain: (data) => ipcRenderer.send('message', data)
});

// renderer.js
window.api.sendToMain({ text: 'Hello Main' });

// main.js
ipcMain.on('message', (event, data) => {
  console.log('Received:', data);
});
```

### 4.2 双向通信（请求-响应）

```javascript
// preload.js
contextBridge.exposeInMainWorld('api', {
  invokeMain: (data) => ipcRenderer.invoke('action', data)
});

// renderer.js
const result = await window.api.invokeMain({ command: 'getData' });

// main.js
ipcMain.handle('action', async (event, data) => {
  // 执行操作
  return { status: 'success', data: processed };
});
```

### 4.3 主进程 → 渲染进程推送

```javascript
// main.js
mainWindow.webContents.send('update', { progress: 50 });

// preload.js
contextBridge.exposeInMainWorld('api', {
  onUpdate: (callback) => {
    ipcRenderer.on('update', (event, data) => callback(data));
  }
});

// renderer.js
window.api.onUpdate((data) => {
  console.log('Progress:', data.progress);
});
```

## 5. 常见陷阱与解决方案

### 5.1 错误：在渲染进程直接使用 `require`

```javascript
// ❌ 错误
const fs = require('fs'); // ReferenceError: require is not defined

// ✅ 正确：通过 Preload 暴露
// preload.js
contextBridge.exposeInMainWorld('api', {
  readFile: (path) => fs.promises.readFile(path, 'utf8')
});
```

### 5.2 错误：暴露过多 API 导致安全漏洞

```javascript
// ❌ 危险：暴露整个模块
contextBridge.exposeInMainWorld('fs', require('fs'));

// ✅ 安全：只暴露必要的方法
contextBridge.exposeInMainWorld('fileAPI', {
  readConfig: () => fs.promises.readFile('./config.json', 'utf8')
});
```

## 6. 总结

### 核心要点

1. **主进程**：应用的大脑，管理生命周期和窗口，完全访问 Node.js
2. **渲染进程**：应用的界面，显示网页内容，**默认隔离** Node.js
3. **Preload 脚本**：安全的桥梁，在隔离环境中暴露受控的 Node.js 功能
4. **上下文隔离**：通过 `contextBridge` 确保渲染进程无法访问未授权的 Node.js API
5. **安全配置**：`nodeIntegration: false` + `contextIsolation: true` + Preload = 最佳实践

### 设计原则

> **最小权限原则**：只暴露渲染进程真正需要的功能，永远不要直接暴露 Node.js 全局对象或模块。

通过正确理解和使用这三个核心概念，你可以构建安全、高效且可维护的 Electron 应用。
