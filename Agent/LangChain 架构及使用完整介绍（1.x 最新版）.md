# LangChain 架构及使用完整介绍（1\.x 最新版）

本文基于 **LangChain 1\.0\+ 正式稳定版本** 编写，全面讲解 LangChain 核心定位、分层架构、六大核心组件、LCEL 编排、LangGraph 进阶能力、工程使用流程、版本迭代差异与生产最佳实践，是面试、入门、落地一体化权威文档。

## 一、LangChain 核心定位与本质

### 1\. 是什么

LangChain 是**大模型 LLM 应用开发框架**，专门用于构建「上下文感知、具备推理能力、可调用外部资源」的 AI 应用与智能体 Agent。

它不生产大模型，**只做模型能力的组装、编排、工程化落地**，解决原生大模型只能单次聊天、无法持久记忆、无法调用工具、无法自动化多轮任务的短板。

### 2\. 核心价值（为什么必须用 LangChain）

- **统一模型抽象**：一套代码兼容 GPT、Claude、通义千问、Llama 等所有主流大模型，无感切换

- **组件化拼装**：提示词、记忆、检索、工具、链路可自由组合，快速搭建复杂业务

- **链路编排能力**：支持线性链式、分支、循环、多轮迭代工作流

- **工程化生产可用**：可观测、可调试、可监控、可版本管理，告别手写 Prompt 玄学

- **Agent 自主能力**：支持 ReAct 推理、工具自主选择、任务自主拆解与闭环

### 3\. 生态三件套（1\.x 官方标准）

- **LangChain**：上层应用封装、快速开发、LCEL 编排、通用组件

- **LangGraph**：底层状态机运行时，负责复杂循环、分支、持久化、断点续跑

- **LangSmith**：可视化调试、链路追踪、日志监控、效果评估、版本管理

**重点更新**：LangChain 1\.x 彻底重构架构，底层统一基于 LangGraph 运行，不再是简单线性 Chain，全面支持生产级长流程智能体。

## 二、LangChain 整体分层架构（三层核心架构）

1\.x 版本统一标准三层架构，层级清晰、解耦彻底，是面试核心考点。

### 1\. 第一层：模型抽象层（基础底座）

负责对接所有大模型、统一入参出参、统一调用协议，屏蔽各家模型 API 差异。

包含：LLM 文本模型、Chat 对话模型、Embedding 向量模型。

### 2\. 第二层：LCEL 工作流编排层（核心能力层）

LCEL（LangChain Expression Language）是 LangChain 1\.x 核心编排语法，替代旧版 Chain 硬编码。

支持组件自由拼接、流式输出、异步执行、参数透传、中间件拦截，实现灵活的业务链路组装。

### 3\. 第三层：Agent 智能体业务层（应用出口）

基于下层模型与编排能力，封装高可用智能体能力：工具调用、记忆管理、RAG 检索、多轮循环、任务自愈闭环。

## 三、六大核心组件（LangChain 能力全集）

LangChain 所有业务能力均由六大模块化组件构成，可单独使用、可自由组合。

### 1\. Models 模型组件（大脑）

框架最底层能力，统一抽象所有大模型能力。

- **LLM**：纯文本输入输出，适合简单生成、改写、总结

- **ChatModel**：对话式消息结构（System/User/Assistant），支持多轮上下文

- **Embedding**：文本向量化，用于相似度检索、RAG 知识库

### 2\. Prompts 提示词组件（指令规范）

将手写 Prompt 工程化、模板化、可复用。

- 支持角色设定、变量动态渲染、格式约束、边界说明

- 内置 FewShot、CoT 思维链模板

- 统一结构化输出规范，降低模型幻觉

### 3\. Output Parsers 输出解析器（结构化兜底）

专门解决大模型自由文本不可解析问题，配合 **Pydantic 约束**，强制模型输出 JSON、列表、键值对等结构化数据，适配程序自动化解析。

### 4\. Memory 记忆组件（上下文持久化）

让大模型拥有「长期记忆」，突破单轮对话限制。

- 短期记忆：对话窗口缓存

- 长期记忆：向量记忆、摘要记忆、实体记忆

- 支持记忆压缩、去重、过期清理，解决上下文溢出

### 5\. Retrievers \& RAG 检索组件（外部知识）

LangChain 最核心落地场景，完整私有知识库流水线。

- **Document Loaders**：加载 PDF/Word/网页/数据库/CSV 各类文档

- **Text Splitter**：递归字符分割、语义分割、Token 分割，解决超长上下文

- **VectorStore**：对接 Chroma、FAISS、Pinecone 等主流向量库

- **Retriever**：相似度检索、多路召回、重排序

### 6\. Tools \& Agents 工具与智能体（行动能力）

让大模型从「只会说话」变成「会主动干活」。

- **Tools**：自定义能力封装（SQL查询、爬虫、计算、接口调用），基于 Pydantic 做参数强约束

- **Agent**：基于 ReAct 范式，自主思考、自主选工具、自主迭代、自主闭环

## 四、核心核心：LCEL 链路编排机制

### 1\. 什么是 LCEL

LCEL（LangChain Expression Language）是 LangChain 1\.x **唯一官方编排方式**，替代 0\.x 老旧 Chain 固定链路。

本质是一套**组件流式拼接语法**，通过管道符 `|` 自由组合模型、提示词、解析器、检索、工具，灵活构建业务工作流。

### 2\. LCEL 核心优势

- 流式输出，响应速度更快

- 天然支持异步、并发

- 中间件可拦截、可日志、可校验、可重试

- 链路可观测，完美适配 LangSmith

- 组件完全解耦，可随时替换、复用

## 五、进阶核心：LangGraph 循环工程架构

LangChain 1\.x 彻底拥抱 **Loop 循环工程范式**，底层全部基于 LangGraph 状态机实现。

### 1\. LangGraph 定位

LangGraph 是**有状态、可循环、可分支、可持久化**的 Agent 运行时，专门解决传统 Skill 单次执行无法闭环的问题。

### 2\. 核心能力（Skill 旧范式完全不具备）

- 目标驱动，而非指令驱动

- 支持循环迭代、结果校验、失败自愈、自动重试

- 状态持久化、断点续跑、长任务不丢失

- 分支判断、多路径调度、复杂工作流

- 人工介入、人机协作、任务审批

### 3\. 层级关系（面试必背）

**LangChain = LCEL 轻量编排 \+ LangGraph 重度循环运行**

简单线性任务用 LCEL，复杂自主 Agent 任务用 LangGraph Loop。

## 六、LangChain 标准使用流程（落地全流程）

所有 LangChain 项目，统一遵循以下工程流程：

1. **环境初始化**：安装依赖、配置模型密钥、接入向量库

2. **组件拼装**：定义 Prompt 模板、配置模型、定义工具、设置记忆

3. **链路编排**：LCEL 组装线性流程 / LangGraph 搭建循环工作流

4. **参数约束**：Pydantic 约束工具入参、输出结构化解析

5. **调试观测**：LangSmith 追踪每一步调用、排查幻觉与报错

6. **上线迭代**：版本管理、Prompt 迭代、链路优化、能力复用

## 七、0\.x 与 1\.x 核心版本迭代差异

|对比维度|LangChain 0\.x（旧版、已淘汰）|LangChain 1\.x（新版、生产主流）|

|状态管理|无状态、临时对话|有状态持久化、断点续跑|

|核心范式|Skill 单次工具调用|Loop 目标驱动全自动闭环|

## 八、核心概念关联总结（打通全书体系）

- **Prompt工程**：负责单轮输出质量（基础 1\.0）

- **Skill工具**：负责单次能力执行（过渡 2\.0）

- **LangChain LCEL**：负责多步骤线性链路编排

- **LangGraph Loop**：负责复杂自主迭代、自愈闭环（当前 3\.0 主流）

- **Pydantic约束**：全链路参数规范化、降低幻觉、保障稳定

- **ReAct**：Loop 内部的模型推理范式，负责每一步思考与行动
