# 客户端Agent开发工程师 面试通关文档
> 适配：百度 DuMate 桌面智能体、PC 端智能体、客户端 AI Agent 研发岗

## 一、岗位核心定位（面试开场白必背）
客户端 Agent = **桌面客户端工程能力 + 本地智能体运行时能力**

和普通前端 / 客户端最大区别：
不只是画界面，能本地自主执行任务
具备 **本地 RAG、本地工具调用、本地记忆、沙箱安全、任务自主规划**

受限环境运行：内存有限、无稳定网络、本地文件权限复杂

核心价值：把大模型能力落地到用户本机，实现全自动桌面办公智能体

## 二、客户端基础面试（必问）
### 1. Electron 进程模型
- **主进程**：唯一拥有系统权限，负责文件读写、窗口、打包、更新、权限管理、网络请求
- **渲染进程**：UI 页面、对话展示、流式渲染，无系统权限
- **IPC 通信**：渲染进程 → 主进程 → 本地 Agent 引擎（Go）

> 面试标准答案：
> Electron 采用多进程隔离，UI 和系统权限分离，保证安全与稳定性，所有本地文件、系统操作必须通过主进程中转。

### 2. 什么是桌面端流式对话？原理
用户看到的 "逐字打字机" 不是一次性返回，是SSE / WebSocket 流式分片返回。

**流程：**
1. 客户端发起 `stream=true` 请求
2. 大模型逐 token 返回二进制流
3. 客户端持续 buffer 拼接、节流渲染
4. 断网缓存、续连、去重、防抖

**难点（面试常问）：**
- 分片乱序、粘包处理
- 断连续答
- 打字机卡顿、频繁渲染阻塞 UI
- 超长对话内存膨胀

### 3. 桌面客户端和 Web 端 AI 的最大区别
- 有本地文件系统权限（最大区别）
- 可离线运行
- 内存、显存严格受限
- 需要沙箱安全管控
- 需要任务持久化、断点续跑
- 三端系统兼容性复杂

## 三、客户端 Agent 核心四大模块（面试核心重点）
> 所有面试官最终只问这四块：本地记忆系统 Memory、任务规划与 ReAct 循环、本地工具调用 Function Calling、客户端本地 RAG

### 1）Agent 记忆系统（高频必考）
**三层记忆体系（客户端 Agent 标准架构）**

- **短期记忆（会话记忆）**
存在内存 / MMKV
当前对话上下文窗口
超过窗口自动滑动窗口截断 / 摘要压缩

- **中期记忆（任务记忆）**
SQLite 持久化每一步任务状态
实现：重启续跑、断点恢复、任务不丢失

- **长期记忆（用户记忆）**
本地向量库存储历史问答、用户习惯、文档知识
新任务自动召回相关历史

> 面试话术：
> 客户端 Agent 必须分层记忆，因为本机资源有限、程序经常重启、网络不稳定，不能完全依赖模型上下文。

### 2）Agent ReAct 自主执行循环（重中之重）
> 客户端智能体核心灵魂，面试官必问

**标准闭环**
`思考 (Reason) → 行动 (Act) → 观测 (Observe) → 再思考`
1. LLM 分析用户需求，判断是否需要工具
2. 输出结构化 Function Calling
3. 客户端本地执行文件 / 系统工具
4. 获取执行结果回填上下文
5. 循环直到任务结束

**客户端独有难点**
- 本地工具不稳定（文件损坏、权限不足）
- 任务耗时久，必须异步调度、状态保存
- 必须限制最大循环次数，防止死循环

### 3）客户端 Function Calling 完整链路（必考流程题）
> 完整流程（背下来）
1. 客户端注册工具描述（名称、功能、入参、格式）
2. 用户提问传入大模型
3. 模型判断需要调用工具，输出JSON 结构化指令
4. 客户端解析、参数校验、类型校验、安全校验
5. 本地执行文件读写 / 文档解析 / 系统操作
6. 执行结果格式化
7. 结果塞回上下文，继续推理输出答案

**客户端独有安全机制**
- 文件路径白名单
- 禁止系统高危指令
- 工具超时强制终止
- 大文件操作加锁防冲突

### 4）客户端本地 RAG（桌面 Agent 必考）
> 和云端 RAG 完全不同！

**客户端 RAG 流程**
`本地文档 → 解析 → 清洗 → 切片 → 本地 Embedding → 本地向量库存储 → 混合检索 → 重排 → 注入 Prompt`

**客户端 RAG 三大难点（面试高频）**
1. 本地设备性能差：切片不能太大、向量不能太多
2. 文档格式杂乱：PDF/Excel/Word 解析容错
3. 检索速度必须极快（用户可感知）

**客户端优化方案**
- BM25 + 向量 混合检索
- 本地轻量 Embedding 模型
- LRU 缓存热点向量索引
- 增量更新知识库
- 本地 Rerank 轻量重排

## 四、Agent Harness 运行时引擎（DuMate 专属考点）
> 面试官问：你们桌面智能体如何实现自主任务执行？

**标准答案模板：**
客户端 Agent 需要一个本地运行时 Harness，负责：
- 任务状态机管理（待执行 / 执行中 / 成功 / 失败）
- ReAct 循环调度
- 工具调用队列（防止并发冲突）
- 断点持久化
- 沙箱安全拦截
- 超时、重试、熔断

> 一句话：
> Harness 是本地智能体的操作系统，控制智能体所有行为。

## 五、客户端 Agent 工程优化面试题（高频）
### 1. 长对话内存爆炸怎么解决？
- 上下文滑动窗口截断
- 历史对话摘要压缩
- 非关键消息丢弃
- 对话数据分页懒加载
- 闲置对话内存释放

### 2. 本地任务卡顿、阻塞 UI 怎么解决？
- 所有 Agent 任务异步队列化（Go 协程 / 异步任务池）
- 耗时文档解析后台线程执行
- UI 主线程只负责渲染
- 任务优先级调度

### 3. 如何防止 Agent 乱改本地文件？
- 路径白名单机制
- 文件操作权限最小化
- 高危操作二次确认
- 沙箱隔离执行环境
- 操作日志全程记录

### 4. 断网情况下智能体如何工作？
- 本地缓存 Prompt 模板
- 本地轻量模型推理
- 本地向量库检索
- 本地工具正常执行
- 联网后同步结果

## 六、Go + TS 双栈面试重点（DuMate 必问）
### 1. 为什么客户端 Agent 需要 Go？
- Go 协程超高并发，适合大量异步 Agent 任务
- 适合做本地引擎、任务调度、向量服务、文件处理
- 内存占用极低，适合客户端受限环境
- 可编译单文件，跨平台无依赖

### 2. TS/Electron 负责什么？
- 流式渲染、对话 UI、状态管理
- IPC 调用本地 Agent 引擎
- 用户拖拽、文件上传、任务进度展示

> 技术架构总结（面试官最爱听）
> TS 负责交互，Go 负责智能体内核，Electron 负责桌面载体

## 七、桌面 Agent 与 普通 Web AI 的区别（必背对比题）
- Web AI：只聊天、无本地权限、纯云端
- 客户端 Agent：可操作本机文件、可离线、可自主多步骤任务、有沙箱、有本地记忆、有本地 RAG

> 一句话区别：
> Web AI 是问答工具，客户端 Agent 是可自主干活的本地数字员工。
