## 一、岗位认知 \& 项目匹配必答题（开场必考）

### 1\. 你理解的 DuMate 桌面智能体是什么？和普通AI对话有什么区别？

**标准答案：**

DuMate 是面向桌面端的**本地自主智能体**，区别于普通网页对话AI，它不只是单纯聊天，而是可以**在用户电脑本地自主完成多步骤办公任务**。

普通Web AI只有云端问答能力，无本地权限、无法操作系统文件；而DuMate桌面智能体具备完整的本地能力，包括本地工具调用、离线RAG检索、分层记忆持久化、自主任务调度，能真正落地文件处理、文档问答、批量办公等复杂任务。

### 2\. 你理解的 Agent Harness 是什么？解决了什么问题？

**标准答案：**

Agent Harness 是桌面智能体的**本地运行时内核与调度基座**，属于Agent Infra基础设施的核心模块。

它主要解决云端框架无法适配桌面端的问题：统一管理智能体的任务状态机、ReAct循环调度、工具调用队列、断点续跑、安全沙箱拦截、超时重试与异常熔断。

上层Electron UI只负责交互展示，所有智能体自主执行逻辑全部由Harness管控，实现UI与智能体内核解耦，保障多步复杂任务在本地稳定、安全、可续跑。

### 3\. 什么是 Agent Infra（智能体基础设施）？包含哪些核心能力？

**标准答案：**

Agent Infra 是支撑上层智能体应用的底层基础设施，目的是把任务调度、工具管理、记忆存储、安全管控、检索能力统一抽象封装，让上层业务无需重复开发底层能力。

核心包含五大模块：

1\. Agent Harness 任务调度内核；

2\. 本地工具调用与安全沙箱体系；

3\. 短期/中期/长期分层记忆系统；

4\. 本地RAG与向量检索服务；

5\. 异常重试、超时熔断、日志监控基建。

### 4\. 你了解的智能体框架 Dify、OpenClaw 有什么区别？

**标准答案：**

Dify 主打**云端低代码智能体编排**，适合快速搭建云端对话工作流，偏向业务应用层，缺少本地任务调度、断点续跑、桌面端沙箱能力。

OpenClaw 主打**通用智能体运行时**，提供ReAct调度、工具调用、任务拆解基础能力，但偏向服务端设计，没有适配桌面端的内存限制、系统权限、离线场景。

而 DuMate 自研的 Agent Harness 是**桌面端专属改造版本**，针对性解决本地文件安全、任务断点续跑、低内存适配、跨系统兼容、离线运行等桌面特有问题。

## 二、技术栈核心题（Go \+ TS \+ Electron）

### 1\. 为什么桌面Agent采用 Go \+ TS 双栈架构？能不能全用TS？

**标准答案：**

不能全用TS。Electron的JS/TS是单线程模型，遇到多并发ReAct循环、批量工具调用、大文件解析、长任务调度，容易阻塞事件循环，造成UI卡顿、任务卡死。

架构分工非常明确：

TS/Electron：负责视图渲染、流式对话展示、用户交互、IPC通信、页面状态管理；

Go：负责Agent内核，利用轻量协程实现高并发任务调度、工具队列管控、文件处理、向量检索、状态持久化，内存占用低、跨平台性好，非常适合客户端受限环境。

双栈通过IPC解耦，兼顾**UI流畅度**和**智能体任务稳定性**。

### 2\. Electron 进程模型是什么？如何保障本地操作安全？

**标准答案：**

Electron 采用经典三进程隔离：渲染进程、主进程、预加载进程。

渲染进程无任何系统权限，只做UI渲染；所有文件读写、系统调用、工具执行全部收敛到主进程；预加载脚本通过contextBridge做安全桥接，隔离前端裸JS权限。

所有智能体工具调用、本地文件操作都必须经过主进程\+Go内核双重校验，杜绝越权访问和恶意操作。

### 3\. 跨平台桌面开发（Windows/Mac/Linux）会遇到哪些问题？怎么解决？

**标准答案：**

常见问题：系统文件路径格式差异、权限模型不同、打包体积差异、系统API不兼容、文件读写权限受限。

解决方案：统一路径适配层、权限最小化设计、跨平台条件编译、统一异常兜底、打包分层优化，保证一套代码多端稳定运行。

## 三、Agent 核心业务面试题（重中之重）

### 1\. 完整讲一遍客户端 Function Calling 全链路

**标准答案：**

第一步：客户端提前注册所有本地工具元数据，包含工具名、功能描述、入参格式；

第二步：用户提问后，客户端拼接系统提示、工具描述、用户问题，整体打包Prompt下发大模型；

第三步：大模型推理判断需要调用工具，返回标准化JSON调用指令；

第四步：客户端Agent Harness做安全校验、参数校验、路径白名单校验、去重拦截；

第五步：通过Go内核执行本地真实文件/系统工具操作；

第六步：规整执行结果，回填对话上下文；

第七步：进入ReAct循环，继续推理直至任务完成，最终输出自然语言答案。

### 2\. 什么是 ReAct 循环？桌面端为什么必须靠它？

**标准答案：**

ReAct 是智能体自主执行的核心闭环，即 **推理思考 → 工具行动 → 结果观测 → 再次思考**。

桌面办公任务大多是多步骤复杂任务，单轮对话无法完成，必须通过循环拆解子任务、多次调用工具、逐步执行，最终完成完整业务流程，是智能体区别于普通问答AI的核心能力。

### 3\. 你的三层记忆架构是怎么设计的？各自用什么存储？

**标准答案：**

我在项目中实现了客户端三层分层记忆，适配桌面重启、断网、长对话场景：

1\. **短期记忆（内存\+MMKV）**：保存当前对话上下文、实时流式进度，负责单次对话连续输出；

2\. **中期记忆（SQLite）**：结构化存储任务列表、对话记录、工具调用日志，实现程序重启后任务断点续跑；

3\.**长期记忆（本地向量库）**：存储文档知识、用户习惯、历史交互语义，通过相似度检索跨会话召回知识，减少模型幻觉。

### 4\. MMKV 和 SQLite 区别，业务上怎么分工？

**标准答案：**

MMKV 主打**超高频率轻量读写**，基于mmap内存映射，速度极快，专门存流式进度、实时任务状态、临时配置快照；

SQLite 主打**结构化持久化存储**，支持事务和复杂查询，专门落库历史任务、完整对话、工具执行记录。

两者互补，MMKV保流畅，SQLite保数据稳定。

### 5\. 本地RAG完整流程是什么？桌面端相比云端RAG有什么难点？

**标准答案：**

完整流程：本地文档解析 → 文本清洗 → 语义切片 → 本地Embedding向量化 → 存入本地向量库 → 用户问题向量化 → 混合相似度检索 → 结果重排 → 注入Prompt问答。

桌面端难点：设备性能参差不齐、内存受限、文档格式杂乱、隐私禁止上传云端、必须离线可用、检索速度要求用户可感知。

优化方案：采用轻量本地Embedding、BM25\+向量混合检索、热点向量LRU缓存、增量更新知识库。

## 四、工程优化 \& 难点面试题

### 1\. 长对话内存爆炸、上下文溢出怎么解决？

**标准答案：**

通过多种手段综合治理：上下文滑动窗口截断、长对话智能摘要压缩、非关键消息丢弃、对话数据分页懒加载、闲置对话内存主动释放、长期记忆替代冗余上下文。

### 2\. 如何防止智能体乱改用户本地文件，安全体系怎么做？

**标准答案：**

搭建桌面端专属沙箱安全体系：文件路径白名单机制、操作权限最小化、高危指令拦截、文件操作加锁、工具超时强制熔断、全程操作日志记录，杜绝智能体越权操作。

### 3\. 弱网/断网场景，你的智能体如何工作？

**标准答案：**

断网下可完整使用本地能力：本地工具执行、本地向量库检索、本地记忆召回、本地轻量模型推理，保证基础办公任务可用；联网后自动同步任务结果与日志，实现弱网适配。
